1. WHAT IS THIS PROJECT
────────────────────────────────────────────────────────────────────────────────

Wizardocs is a domain-specific RAG (Retrieval-Augmented Generation) Q&A system
for ML and LLM documentation. Users ask a question, the system retrieves the
most relevant chunks from an indexed documentation corpus, and GPT-4o-mini
generates a grounded answer with inline citations ([1], [2]) that link back to
the exact source chunk.

The product is positioned as a SaaS tool:

  Free tier  — $0 forever
    · Ask anything — LangChain docs included
    · 10 chats stored, messages kept for 2 most recent
    · 100 queries / month
    · Inline citations + confidence meter

  Pro        — $29/month
    · Save & bookmark answers
    · Upload your own docs (PDFs, Markdown, Notion)
    · Full history — messages kept for all 10 chats
    · Export conversations as Markdown or PDF
    · Unlimited queries
    · Ask across multiple doc sources at once

  Team       — $99/month
    · Everything in Pro
    · Up to 20 seats, shared workspaces
    · SSO / SAML, dedicated support

Current corpus: LangChain documentation only (3,235 deduplicated chunks).
Roadmap corpus: HuggingFace, MLflow, RAG writing, Vector DB blogs.
Future: users upload their own docs (bring-your-own-docs, Pro feature).

6. KEY ARCHITECTURAL DECISIONS (with rationale)
────────────────────────────────────────────────────────────────────────────────

DECISION: No bundler (Vite, webpack) for the frontend
  Vanilla React via CDN. No npm, no build step. Fast iteration, easy to
  deploy alongside FastAPI. Tradeoff: no TypeScript, no tree-shaking.
  Migrate to Vite when codebase grows large enough to warrant it.

DECISION: ChromaDB (local) over Pinecone/Weaviate
  File-based, zero infra, Docker volume mounted. Sufficient for single-tenant
  and small multi-tenant workloads. Migrate to Qdrant or Weaviate when corpus
  exceeds ~1M chunks or BYOD needs horizontal scaling.

DECISION: GPT-4o-mini
  Low cost, fast, good instruction following for citation-only prompts.
  The strict system prompt matters more than model choice for grounded RAG.

DECISION: Cohere reranker
  Cross-encoder significantly improves precision over pure BM25+vector.
  Alternative: local bge-reranker-base (slower but free).

DECISION: RRF fusion (not score normalization)
  BM25 scores and vector cosine scores are on different scales. RRF uses
  only rank position — scale-independent, no tuning. Standard k=60.

DECISION: Supabase (not SQLAlchemy + self-hosted Postgres)
  Provides auth (Google/GitHub OAuth), managed Postgres, JWT (JWKS/ES256),
  and RLS in one service. Target audience all have Google accounts.

DECISION: Stateless history injection (not server-side sessions)
  Frontend sends last 6 messages with each /ask. Backend is stateless.
  Messages are already in React state and DB — no Redis needed.

DECISION: Retrieval query = current question + last user turn
  Retrieval uses only the current question (enriched with last user turn for
  follow-ups). Full conversation history is only passed to the LLM call.
  This keeps retrieval sharp — embedding a paragraph produces noisier results.

DECISION: JWT verified via JWKS (ES256, not HS256)
  Supabase issues ES256 tokens. PyJWKClient fetches the public key from
  the JWKS endpoint. HS256 with the JWT secret does not work.

DECISION: Cap rule — messages only for last 2 chats
  Supabase free tier has limited storage. Messages are large (full LLM output).
  Cap: 10 chats stored (titles), messages only for 2 most recent.
  Pro feature: messages for all 10 chats.

7. DATABASE SCHEMA (as deployed)
────────────────────────────────────────────────────────────────────────────────

  users_profile   (id uuid PK refs auth.users, name text, plan text default 'free',
                   created_at timestamptz)
  workspaces      (id uuid PK, owner_id uuid refs users_profile, name text,
                   created_at timestamptz)
  chats           (id uuid PK, workspace_id uuid refs workspaces, title text,
                   created_at timestamptz)
  messages        (id uuid PK, chat_id uuid refs chats, role text, content text,
                   sources_json jsonb, created_at timestamptz)
  query_usage     (user_id uuid PK, count int default 0, period_start date)
  chunk_usage     (workspace_id uuid PK, chunks_indexed int default 0)

  Cap rule enforced in api/db.py create_chat():
    - New chat pushes existing chats down by 1 position
    - Chat falling to position 3: its messages are deleted
    - Chats at position 10+: the whole chat is deleted (CASCADE removes messages)

9. ARCHITECTURE & REQUEST FLOW
────────────────────────────────────────────────────────────────────────────────

OFFLINE — One-time ingestion (scripts/ folder, already done)
  1. Scrape    scripts/ download LangChain HTML pages
  2. Parse     HTML → clean text (trafilatura / BeautifulSoup)
  3. Chunk     Semantic chunking, heading-aware, deduped → chunks.jsonl (3,235 chunks)
  4. Embed     OpenAI text-embedding-3-small in batches → stored in ChromaDB (chroma_db/)
  5. BM25      BM25Okapi index built in-memory from chunks.jsonl on every server startup

─────────────────────────────────────────────────────────────────

ONLINE — Every POST /ask request

  Browser (React)
    │
    │  POST /ask  { question, chat_id, history[last 6 messages] }
    │  Authorization: Bearer <Supabase ES256 JWT>
    ▼
  FastAPI  api/main.py
    │
    ├── auth.py
    │     PyJWKClient fetches public key from Supabase JWKS endpoint
    │     Verifies ES256 JWT signature → extracts user_id (sub claim)
    │     Returns 401 if token missing, expired, or invalid
    │
    └── generator.ask(question, history)
          │
          ├─ [1] RETRIEVAL QUERY ENRICHMENT
          │       If history exists → prepend last user turn to current question
          │       Reason: "explain more" alone has no keywords; enrichment
          │       keeps the retriever anchored to the right topic
          │
          ├─ [2] HYBRID RETRIEVAL  (hybrid_retriever.py)
          │   ├─ BM25 search     → tokenize query → score all 3,235 chunks
          │   │                    → top 20 keyword matches
          │   ├─ Vector search   → embed query (text-embedding-3-small)
          │   │                    → ChromaDB cosine similarity → top 20
          │   └─ RRF fusion      → score(chunk) = Σ 1 / (60 + rank_i)
          │                         scale-independent; chunk in both lists
          │                         scores higher → merged top 20 candidates
          │
          ├─ [3] RERANK  (reranker.py)
          │       Cohere rerank-english-v3.0 cross-encoder
          │       Reads (query, chunk_text) pairs together → relevance score
          │       Top 20 → top 5 chunks, each with rerank_score (0-1)
          │
          ├─ [4] GENERATE  (generator.py + llm.py)
          │   ├─ formatter.py   "[1] chunk_text [2] chunk_text ..."
          │   ├─ GPT-4o-mini
          │   │     system: cite every claim with [N], strict grounding (prompt.py)
          │   │     messages: conversation history + formatted context + question
          │   ├─ parser.py      extract [N] refs → map to {title, url} metadata
          │   └─ confidence     = chunks[0].rerank_score  (top Cohere score, 0-1)
          │
          └─ [5] FOLLOWUPS  (llm.py)
                  GPT-4o-mini: question + answer[:400] → 3 context-specific questions
                  max_tokens=150, temp=0.7; fails safe to [] on any error

    Response: { answer, sources[{number, title, url}], confidence, followups }

  SIDE EFFECTS (fire-and-forget after response is ready)
    ├─ db.save_messages()         saves user + assistant turns to Supabase messages
    └─ db.increment_query_count() upserts query_usage (user_id, period_start, count++)

    ▼
  Browser (React)  ←  { answer, sources, confidence, followups }
    ├─ Animates answer text character-by-character (simulated streaming)
    ├─ Renders [N] citation pills inline — hover preview, click opens source URL
    ├─ Source cards below answer (title, URL, Cohere match score)
    ├─ Confidence meter reads data.confidence (Cohere reranker score 0-1)
    └─ Followup pills above compose — click to pre-fill textarea

─────────────────────────────────────────────────────────────────

AUTH FLOW (separate from /ask)

  1. User clicks "Sign in with Google" → supabase.auth.signInWithOAuth()
  2. Redirect to Google → back to app with ?code= in URL
  3. Supabase exchanges code → issues ES256 JWT, stores in localStorage
  4. app.jsx onAuthStateChange("SIGNED_IN") fires
       → if already on chat/profile: stay (tab-refocus safe)
       → otherwise: go to landing (shows authed nav)
  5. INITIAL_SESSION fires on mount → restore last page or go to landing
  6. All API calls attach: Authorization: Bearer <access_token>
